# PBMC3k real-data reference fixture

This directory contains a small, deterministic derivative of the 10x Genomics
3k PBMC count matrix. It is committed directly to Git so ordinary tests can use
real count structure without network access, Git LFS, or stochastic fixture
generation.

The two matrices have the same 256 cells and 1,024 genes, in the same order:

- `pbmc3k_raw_counts.npz` contains the selected cells and genes at their
  observed depths. It retains cell-depth variation for normalization and
  transform oracle tests.
- `pbmc3k_equal_depth_counts.npz` is an exact 1,000-count-per-cell molecule
  subsample of that restriction. It supports the controlled fixed-offset
  SCTransform comparison.
- `manifest.json` records source and artifact checksums plus a few count totals
  that catch corruption or accidental artifact replacement.
- `generate_fixture.py` is the complete provenance and regeneration tool.

The checked-in matrices are SciPy CSR NPZ files with `int32` counts. Tests must
consume these pinned artifacts and must not download or regenerate them
silently.

## Deterministic selection

Selection is performed on the original 2,700-cell by 32,738-gene matrix:

1. Compute each cell's total over all source genes and retain cells with at
   least 2,500 counts. There are 944 eligible cells.
2. Rank eligible cells by the raw SHA-256 digest of
   `pbmc3k-cell-v1:<barcode>`, take the first 256, and restore original source
   order.
3. Within those 256 cells, rank genes by descending total count, breaking ties
   by Ensembl ID and source index, and take the first 128.
4. Among remaining genes detected in at least 30 selected cells, rank the raw
   SHA-256 digest of `pbmc3k-gene-v1:<Ensembl ID>` and take the first 896.
5. Combine those 1,024 genes and restore original source order.

Restoring source order makes the matrices easy to trace back to the source;
selection itself does not depend on input row ordering where an identity is
available.

## Exact equal-depth subsampling

The equal-depth matrix deterministically retains exactly 1,000 molecules from
every selected cell. A source count of `x` for one cell-gene pair is expanded
conceptually into molecule ordinals `0, ..., x - 1`. Each molecule receives a
SHA-256 priority over:

```text
sparse-count-pca/pbmc3k/equal-depth/v1<NUL>
<barcode><NUL><Ensembl ID><NUL><zero-based decimal molecule ordinal>
```

The generator retains the 1,000 molecules with the lexicographically smallest
`(digest, Ensembl ID, ordinal)` keys in each cell and aggregates them back to
counts. This is a reproducible fixed-size molecule subsample that does not
depend on NumPy or SciPy random-number algorithms. Every selected raw row has
at least 1,370 counts, so every cell is genuinely thinned.

The equal-depth fixture has no empty cells or genes. At constant dispersion
`theta = 100` and clip limit `sqrt(256 / 30)`, it contains both upper-tail
clipping and negative clipping at structural zeros; the dense-oracle tests
exercise both behaviors directly.

## SCTransform v2 equality oracle

`sctransform_equal_depth_reference.npz` is a real-data equality oracle generated
by [sctransform 0.4.3](https://github.com/satijalab/sctransform/tree/v0.4.3),
pinned to commit
[`49e35b5aeb76a602910207cbfde1561093340be3`](https://github.com/satijalab/sctransform/commit/49e35b5aeb76a602910207cbfde1561093340be3).
The fit uses `vst.flavor="v2"`, `do_regularize=TRUE`,
`fix_intercept=TRUE`, `fix_slope=TRUE`, and `min_variance=0`. The fixed
intercept makes the final fitted mean equal the empirical mean for every gene;
the fixed slope represents library size as an offset rather than an estimated
cell-depth coefficient.

The artifact contains all 256-by-1,024 centered Pearson residuals, not a sample,
both without clipping and with symmetric clipping at `sqrt(256 / 30)`. It also
contains the final regularized `theta`, `alpha = 1 / theta` with infinite
`theta` mapped to zero, fitted gene means, the clip value, and clipping counts.
Clipping is performed before gene centering, matching the order in the pinned
[Seurat 5.5.1 wrapper](https://github.com/satijalab/seurat/blob/4c0f2dc16fad4e8f0d7b5c98321d8bcb18caa13a/R/preprocessing.R#L4103-L4122).

The generator requires `glmGamPoi` and verifies that sctransform selected its
`glmGamPoi_offset` backend. This test does not claim that fitting backends
estimate identical dispersions. Instead, it supplies this package with the
exact final per-gene `alpha` stored by SCTransform, then tests the shared
residual formula, clipping, and centering over every matrix entry.

## Dense formula regression tests

The same pinned matrices also drive full-matrix comparisons with shared,
independent dense NumPy formulas used by the simulated-data tests. They compare
all 256-by-1,024 transformed entries, and the expected-value paths do not call
production representation builders.

Coverage includes:

- all six Poisson, binomial, and scaled-NB Pearson/deviance residual families;
- upper clipping without support growth and symmetric clipping that adds real
  structural-zero corrections;
- shifted log, count-shifted CLR, and proportion-shifted CLR, including their
  matched-shift identity on the equal-depth fixture;
- Dirichlet log and CLR with uniform and nonuniform priors; and
- classical and experimental scaled-NB correspondence matrices, their masses,
  and total inertia.

The correspondence API currently returns its complete implicit matrix only
with `return_operator=True`, after ARPACK has run. Those tests materialize that
operator on the full standard basis, but use only its matrix values—not its
computed singular vectors—as oracle evidence.

Real-data mask tests additionally apply a deterministic noncontiguous gene
mask to every transform family and compare the complete centered masked
operator with columns selected from the full fitted transform. They include
symmetric residual clipping, all-true and all-false mask boundaries, and a
runtime-appended all-zero gene. The committed count artifacts remain unchanged;
the zero column exists only in memory during those tests.

## Regeneration

With the project environment installed, download the official archive and run:

```bash
curl -L -o /tmp/pbmc3k_filtered_gene_bc_matrices.tar.gz \
  https://cf.10xgenomics.com/samples/cell-exp/1.1.0/pbmc3k/pbmc3k_filtered_gene_bc_matrices.tar.gz

.venv/bin/python tests/real_data_reference/generate_fixture.py \
  /tmp/pbmc3k_filtered_gene_bc_matrices.tar.gz
```

To audit regeneration without touching the committed files, write elsewhere
and compare:

```bash
.venv/bin/python tests/real_data_reference/generate_fixture.py \
  /tmp/pbmc3k_filtered_gene_bc_matrices.tar.gz \
  --output-dir /tmp/pbmc3k-reference-check

cmp tests/real_data_reference/pbmc3k_raw_counts.npz \
  /tmp/pbmc3k-reference-check/pbmc3k_raw_counts.npz
cmp tests/real_data_reference/pbmc3k_equal_depth_counts.npz \
  /tmp/pbmc3k-reference-check/pbmc3k_equal_depth_counts.npz
cmp tests/real_data_reference/manifest.json \
  /tmp/pbmc3k-reference-check/manifest.json
```

To regenerate the SCTransform oracle after auditing the equal-depth fixture,
export it in sctransform's genes-by-cells orientation and run the pinned R
generator:

```bash
.venv/bin/python tests/real_data_reference/export_equal_depth_for_r.py \
  /tmp/pbmc3k_equal_depth_genes_by_cells.mtx

R_LIBS_USER=/tmp/sparse-count-pca-r-lib \
  Rscript tests/real_data_reference/generate_sctransform_reference.R \
  /tmp/pbmc3k_equal_depth_genes_by_cells.mtx \
  tests/real_data_reference/sctransform_equal_depth_reference.npz
```

The generator writes a deterministic NPZ container directly from R. Its
current SHA-256 is:

